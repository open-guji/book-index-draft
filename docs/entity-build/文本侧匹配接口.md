# 文本侧匹配接口（草案）：名字（＋朝代）→ 候选 entity_id

> GUJI-509｜执行：Edwin｜待 Mavis／用户对稿｜基于 GUJI-394 键表（`键表设计.md`）｜脚本 `scripts/entity/match_names.py`｜样例 `匹配样例/`
> 目标：专名先稳定出一个版本，文本按名字能匹配到 ID。本接口只**给候选与信号，不替调用方做最终裁决**。

## 一、输入／输出
**输入**（单条）：`name`（必填，文本里的名字）、`dynasty`（可选，**软信号**）、`subtype`（可选：people／place／office／dynasty／reign／collective，限定范围）。
另有 `id` 模式：给旧 id／草稿 id，返回 live 落点。
**数据源**：`export_keytable.py` 全量导出的 `键表.tsv`＋`重定向表.tsv`（须从 live book-index 仓导出，promotions 在那里）。
**输出**（JSONL 一行一查询）：`status`、`via`、`candidates[]`（`entity_id, primary_name, subtype, dynasty, key_kind, via, dynasty_signal`）、`reason`。

## 二、匹配流程（按序）
1. **精确**：`name` 原字形查 `键表.key`。
2. **异体**：精确无果，查 `norm_key`（同一张异体表；查询名也过 `norm_key()`）。命中时 `via=norm`。
3. 若给了 `subtype`，先按它过滤。
4. **墓碑旧名回退**：键表无果时，查重定向表 `old_name`（merged 墓碑的旧主名）。命中且 final 在 live → `status=tombstone_name`（**较弱**，建议抽检）；final 不在本表 → `none`；仅命中 retired → `retired`。
5. 仍无 → `none`，走缺实体入口（GUJI-395）。

## 三、朝代：软信号，不排除（用户 10-15 定）
帝王等有 16 条朝代标注与年号表不一致（劉協、洪秀全等，清单在 Sidney 处），所以**不要求朝代相等，更不据此排除候选**。
- 每个候选带 `dynasty_signal`：`match`（归一后相等）、`partial`（互相包含，如 宋／北宋、南宋）、`mismatch`、`unknown`（任一方为空）。
- 只用于**排序**：match＞partial＞unknown＞mismatch，同档主名＞别名；所有候选都保留。
- 唯一候选且朝代 mismatch：仍 `unique`，`reason` 提示抽检（如 洪秀全 明≠清 的情形）。

## 四、status 与调用方动作
| status | 含义 | 调用方动作 |
|---|---|---|
| `unique` | 只有一个候选 | 可直接挂；`reason` 带朝代不一致提示时抽检 |
| `likely` | 多候选，仅一条朝代 match，其余降权保留 | 可挂首条，但计入抽检样本 |
| `ambiguous` | 同名多候选，朝代无法裁 | **不得取第一条**；用作品／作者／上下文消歧，仍不能定标「待判」 |
| `redirected` | `--id` 的旧 id／草稿 id 经 merged／promoted 落到 live | 改写为 `candidates[0].entity_id` |
| `tombstone_name` | 名字只命中墓碑旧名，已跟到 final | 弱匹配，抽检后再挂 |
| `retired` | 命中退役条 | 不得取用，报缺 |
| `none` | 键表无此名，或重定向目标不在 live（`promoted-dangling`） | 走缺实体入口／上报 |

## 五、同名、别名、重定向规则小结
- **同名**：同 (subtype, key) 多个 live entity → 全部返回；`cand_n`／`norm_cand_n` 是同一信息的预算值。
- **别名**：别名与主名同级入键（`key_kind=alt:*`），命中别名也返回其所属 entity 的 `primary_name`，让调用方核对是不是想要的人。主名排在别名前，仅为排序。
- **merged**：墓碑条的名不入键；旧 id 经重定向表（已解析到链尾）改指；旧名走第 4 步回退。
- **promoted**：草稿 id→正式 id，校验落 live；`promoted-dangling` 视为 `none` 上报。
- **retired**：不入键表，不返回候选。

## 六、用法（可直接跑）
```bash
# 先导出（给 live book-index 仓；秒级）
python3 -I scripts/entity/export_keytable.py /path/to/book-index /tmp/kt
# 单条
python3 -I scripts/entity/match_names.py /tmp/kt --name 蘇軾 --dynasty 宋 --subtype people
# 旧 id／草稿 id 改指
python3 -I scripts/entity/match_names.py /tmp/kt --id 1jb89swpg2jnk
# 批量：查询.tsv 表头 name[,dynasty,subtype]，结果 JSONL，stderr 打各 status 计数
python3 -I scripts/entity/match_names.py /tmp/kt --batch 匹配样例/查询.tsv --out 结果.jsonl
```
样例 `匹配样例/结果.jsonl` 是用全量键表（源 `141d0d14c8`）跑 `查询.tsv` 的结果：蘇軾／王安石 → unique（partial）、洪秀全（明）→ unique＋朝代不一致提示、陳巖肖 → tombstone_name、不存在的名 → none。

## 七、尚未覆盖（草案边界）
- **书目上下文**（作品、作者、版本）本版不进脚本：脚本只吃名字与朝代；`ambiguous` 的消歧由调用方用上下文做，后续可加 `--author-of` 之类的打分信号，待对稿定。
- 键表只含 Entity，不含 Work 标题；异体表是有限逐字表，不含繁简转换。
- 地名省文（「某縣」省作「某」）、避讳字不处理，缺的走缺实体入口。
- 已知：异体表 `歴→曆` 方向存疑（用户 10-15 定『够用』：避讳／单字／歴／省文先不管）（Sylvie 建议 歴→歷），等 Thaddeus ④ 重跑结果再定，改的话脚本与导出器两处同步。

## 八、书名侧：Work 标题键表（`export_titlekeys.py`／`match_titles.py`）
键表只含 Entity，书名另出一套同构的表（GUJI-509 对稿，用户要求 Edwin 出）。
**导出**：`python3 -I scripts/entity/export_titlekeys.py <live book-index> <输出目录>` → `标题键表.tsv`、`标题重定向表.tsv`、`标题键表.meta.json`（含两表与脚本 sha256）。样例 `标题键表样例/`（前 1500 条 live Work，源 `141d0d14c8`）。
全量实测（源 `141d0d14c8`）：live Work 131,594，键 140,034 行，同名书名 6,579 个，重定向 37,547（merged 510＋promoted 37,037；promoted-dangling 0）。
- 键来源：`title`（primary）、`additional_titles`（alt:additional）、`original_title`（alt:original）。`merged_into` 的 Work 不入键表，走重定向表（并按旧题参与墓碑回退）。
- 列：`key, work_id, primary_title, key_kind, authors（／连接）, dynasty, cand_n, norm_key, norm_cand_n, bare_key`。
- `bare_key`：异体折叠后再去《》与首部时代标记「[光緒]」「（清）」，使「[光緒]光福志」「光福志」「《光福志》」互通；同名异修仍是不同 Work，靠作者／朝代区分，不在 bare 层合并。
- **匹配**（`match_titles.py --title 书名 [--author 作者] [--dynasty 朝代]`）：精确 → norm_key → bare_key → 墓碑旧题。**作者、朝代都是软信号**（`author_signal`／`dynasty_signal`），只降权排序不排除；状态口径同 §四，`likely`＝多候选仅一条作者（无作者时朝代）吻合。`--id` 模式把旧 id／草稿 id 改指现行 Work。
- 样例：`匹配样例/书名查询.tsv`、`书名结果.jsonl`（全量表跑出）：『史記＋司馬遷』→ likely；『論語』『山西通志』→ ambiguous（同名多 Work）。
- 局限：作者按 `authors[].name` 原字形比较（含异体折叠），不含 Entity id 反查；书名省文、卷数混入题名等不处理；Draft 里尚未晋升的 Work 不在 live 表内（须对 draft 仓导出另行跑，用法相同）。
- 另：§二 `subtype=office` 查询现已同时查 `collective`（官署常同时作机构入库）。
