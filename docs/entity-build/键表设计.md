# 专名键表：名／别名 → entity_id 导出与增量规则（一页）

> GUJI-394（K1）｜执行：Edwin｜调用方：文本块（Mavis）｜脚本 `scripts/entity/export_keytable.py`｜样例 `键表样例/`（非人物全量＋人物前 300 条，源 book-index `141d0d14c8`）
> 全量实测：源 `141d0d14c8` → live 实体 37,838，键 68,101 行（键表 2.9MB），歧义键 3,831，重定向 616。

## 一、导出文件（均 UTF-8、TSV、LF、按 (key, entity_id) 排序，同输入逐字节可复现）
**键表.tsv**：`key, entity_id, subtype, key_kind, dynasty, cand_n`
- `key`：库内原字形的名字（`primary_name` 与 `alt_names[].name`），**不做繁简／异体归一**，调用方自行归一后再查（避免键表替调用方定归一规则）。
- `subtype`：people／place／office／dynasty／reign／collective。
- `key_kind`：`primary` 或 `alt:<类型>`（字、號、異寫、…）。
- `dynasty`：人物的 `dynasty`，其余为空；供同名消歧。
- `cand_n`：同 subtype 内以此 key 为名的 live entity 个数。**cand_n=1 可直接取用；>1 为同名歧义，调用方必须结合 dynasty／上下文消歧，不得取第一行。**

**重定向表.tsv**：`old_id, status, final_id, old_name`
- `merged`：墓碑（`merged_into`），`final_id` 已沿链解析到最终 live id；文本里残留的旧 id 一律经此表改指。
- `retired`：退役（`retired:true`），无 `final_id`；这类 id 及其名**不入键表**，遇到即报缺。

**键表.meta.json**：`source_commit`（book-index 全 SHA）、行数、口径。调用方应记录自己用的是哪个 commit。

## 二、入表规则
- 只收 live 条目：无 `merged_into`、非 `retired`。墓碑条的名不入键（其别名应已并入存活条；未并入者不补）。
- 同一 entity 的多个名各占一行；同名同 entity 去重。

## 三、增量规则
- **全量重导为准**：每次对 book-index main 某 commit 全量导出（秒级），不做就地补丁。
- **增量文件**：`export_keytable.py … --prev <旧键表.tsv>` 额外产出 `增量.tsv`（op=add／del／chg，键＝(key, entity_id)；chg＝key_kind 或 dynasty 变化）。调用方按 `meta.source_commit` 对账：旧 commit 与手上一致才可套用增量，否则取全量。
- 触发：book-index 每次合入涉及 `Entity/` 的 PR 后可重导；调用方也可随时自行重导（纯只读脚本）。
- **缺实体**不在键表内表达：查不到 key → 走缺实体需求入口（GUJI-395）。

## 四、调用建议（给文本块）
1. 先 key 精确匹配；无结果再自行做繁简／异体归一重查。
2. 命中后若 `cand_n>1`，用 `dynasty`（及作品上下文）消歧；仍不能定者标「待判」，不要硬挂。
3. 命中旧 id 或需校验已有 `entity_id` 时，查重定向表。

## 五、已知局限
- 不含 Book／Work 里的非 Entity 名字；不含外部 id（CBDB 等）反查。
- 同名歧义 3,831 键（多为人物同名），键表只暴露、不裁决。
