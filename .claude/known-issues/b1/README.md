## 第五檔：純同源著錄重出

`scripts/b1/dup_entry.py`／`dup_entry2.py` 找組內兩條 `indexed_by` 是否共用完全同文
（source＋title_info 全同）之著錄。**這條路徑陷阱極大**：許多志書本就在同一標題卷數
之下臚列數家（如國史經籍志「《周易注》十卷（王肅；荀輝；干寶……）」一條列十餘人），
共用 title_info 只是志書體例，非重出。

**收窄之法**：先只取「組內恰好兩條共用」者（多於兩條，通常是志書列舉數家），
再取其 **summary 全文**（非僅 title_info）逐字相校——全同才判重出。64 對候選中
複核後僅 3 對 summary 全同，其中 2 對（棋勢、楚辭音）核讀後仍非重出：其共用之
著錄本身是「（甲；乙）」之複合句式，正確地雙掛於兩條之下作為佐證，非匯入錯誤。
真重出僅 1 對（胎息訣，兩條除「胎息訣一卷」四字外別無他辨）。

## 第三檔的主脈：整理本另立的無撰人 stub

`scripts/b1/stub_evidence.py` 抓的是這一型：**某志匯入時未繫既有 work，另立了一個
同題同卷、撰人欄空、`indexed_by` 只有一條裸摘要的 work**，而其撰人其實就寫在
該條所繫整理本 section 的正文裡。直齋書錄解題此型最多（宋書、雞肋集、五峰集、
南唐書、春秋比事、文選皆是），舊唐志次之。

**取證之法**：以 stub 所繫 section 之正文是否書有候選之撰人名為據。這比卷數相合
可靠得多，因為卷數相合可能只是巧合。

**一個假陽性**：《神農本草》八卷之隋志節正文確有「陶隱居」三字，然那在「梁有……
《陶隱居本草》十卷」之小注裡，是別書。凡取證命中者仍須讀出上下文。

## 基線之一項必動：`整理本 section 級磁鐵`

**併池會使這一項上升，而那不是損壞。** 該項數的是「異題共指一 work 之題數」；
一書在諸志各有異題（《說林》二十卷／又二十卷張大素撰。／僧一行周易論／周易論三卷），
合併之前各繫各的 work，合併之後同指一條，計數自然增加。批二淨 +2（881→883）。

判別之法：新增之磁鐵若其諸題**同指一書**（異題乃志書體例之異），是併池之果，可過；
若其諸題**實為數書**，才是真磁鐵，當回退。批二新增者逐一核過，皆屬前者。

其餘各項（人物↔作品雙向、Book↔Work、派生欄、JSON 格式、period 不合）**必須與基線全同**。
批二初跑曾使「人物→作品 單向」13→15，因合併後留連之 entity 未回填 keeper 撰人欄之
`entity_id`；已補入 `merge.py`，並手工修《詩評》鍾嶸、《說林》張大素二處。

## merge.py 索引同步之一處已知漂移（2026-08-23 B4 第二批發現）

`scripts/b1/merge.py` 合併後同步 `index/works/*.json`，其 `dynasty` 欄取自
**Work 的 `dynasty` 欄**；而 `chk.py` 的重算值取自 **`authors[0].dynasty`**。
二者在「書之時代與撰人之時代不同」時必然相左。

實例：《江南錄》`1evcsxnyn5pts`，撰人徐鉉、湯悅為**南唐**舊臣，而書成於**宋**太宗時，
故 Work 之 `dynasty` 作「宋」（`dynasty_basis` 記其據），索引之 `dynasty` 原作「南唐」。
本批合併後 merge.py 把索引改寫為「宋」，`chk.py` 遂報「索引欄位不符 1」。已手工復原。

**收工前必查**：每批合併後跑 `chk.py`，見「索引欄位不符」有 `dynasty` 一項，
即以 `authors[0].dynasty` 為準改回索引，**不要動 Work 的 `dynasty`**（那是 C 車道的欄）。
