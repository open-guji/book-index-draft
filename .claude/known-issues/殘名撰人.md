# 已知缺陷：撰人欄只剩殘名（169 條）

**狀態**：已查明成因與範圍，**暫不修**（2026-08-05 決）。清單見同目錄
`殘名撰人.json`（169 條，含 id / title / author / source / summary / path / entity_id）。

## 何以要記下來

這類缺陷**不觸發任何校驗**：欄位有值、非空、無懸空關聯，`chk.py` 全綠。
但它會讓書名與撰人的比對**永遠不合**，於是同一部書被判成「本庫沒有」，
接著被重新建一遍。玉函山房那一輪就險些如此——《四民月令》本已在庫，
差一點又建一個（那次是部首區字所致，機理相同：比對用的字串不是真的那個字串）。

**凡遇「庫中查不到」而準備新建時，先來對一眼這張清單。**

## 兩種成因，不是一種

### 甲、匯入時假定撰人為二字（複姓而無名，14 條）

《清史稿藝文志》原文作「漢公孫弘書一卷」。匯入者取「漢」為朝代，
其後**固定截二字**為撰人，餘者為書名，遂得撰人「公孫」、書名「弘書」。
凡複姓而單名者皆中此招：

| 現 title | 現 author | 原文（見 indexed_by[].summary） | 應為 |
|---|---|---|---|
| 弘書 | 公孫 | 漢公孫弘書一卷 | 公孫弘《書》 |
| 棐集古錄目 | 歐陽 | 宋歐陽棐集古錄目五卷 | 歐陽棐《集古錄目》 |
| 恪諸葛子 | 諸葛 | 吳諸葛恪諸葛子一卷 | 諸葛恪《諸葛子》 |
| 湛新論 | 夏侯 | — | 夏侯湛《新論》 |
| 紹奕石林燕語考異 | 宇文 | — | 宇文紹奕《石林燕語考異》 |

**這一類可機械回復且可自驗**：撰人 = 現 author + title 首字，書名 = title 去首字，
合成之後應與 `indexed_by[].summary` 的原文字串相符——**這個相符就是驗算**，
不合則棄權。同理當疑：三字單姓名（如「司馬相如」之外的「諸葛亮」型）
是否也有反向的截多截少，修時要一併掃。

### 乙、志書原文本來就只寫姓（單字殘名，155 條）

《補晉書藝文志》原文作「春秋左氏函傳義十五卷　干，謹按見《隋志》……
本書寶傳言寶有《春秋左氏義外傳》，即是書」。**志書本身只寫「干」**，
指望讀者自知；全名要從同條的案語裡讀出來（「寶傳」「寶有」→ 干寶）。

這一類**不能機械回復**，須逐條讀案語，與「OCR 缺字：補字要三源」同法。
來源分佈：補晉書藝文志 101、續修四庫全書 15、欽定四庫全書總目 11、
漢書藝文志 11、清史稿藝文志 8，其餘零星。

## 修的時候要留意

- **169 條中有 137 條已繫 `entity_id`**。改 `authors[].name` 就必須同時考那個
  entity 是誰——殘名「華」所繫之 entity 未必就是華嶠。**只改 name 不動 entity
  會造出一個名實不符的關聯**，比現在更難查。
- 甲類改 title 會動到索引 `index/works/*.json` 的 `title`，以及所有
  `related_works[].title`（SCHEMA 要求同步）。
- 已考出而未改者三條，其考證寫在玉函山房整理本的 `link_basis` 裡，可直接取用：
  「華」= 華嶠、「戴」= 戴逵、「皇甫」= 皇甫謐（皆以朝代加書名定，不徒恃姓）。
