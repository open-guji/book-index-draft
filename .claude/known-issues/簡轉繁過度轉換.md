# 已知缺陷：簡轉繁之過度轉換（2026-08-06 已修主要者）

**狀態**：已全庫回改，兩輪共 3,691 處、1,571 檔，改名 96 檔（含 fragments），
並立常駐校驗 `chk.py`「簡轉繁過度轉換」**基線 0**。餘見下「未修者」。

- 第一輪（列詞）：幹寶→干寶、硃→朱、鬆→松、錶→表、釧會→鍾會、範+人名 26 式等，2,511 處。
- 第二輪（立位置之判）：第一輪逐名列舉必有遺漏（範義、範泰、範縝、範雲、範景文、
  範村菊譜、案範書……），改立**姓位之判**——範前一字若是界（引號、書名號、頓逗句號、
  括弧、空白、「案」）則是姓，回作范；否則不動。一判得 1,180 處，而洪範、師範大學、
  桓範集、陳祖範撰、帝範、家範、軌範、懿範皆安然不動。

## 發現之由

析《隋書經籍志》注中亡書時，撰人析出「幹寶」「硃育」「釧會」——皆非其名。
覆按乃知本庫某幾批匯入之文本是由簡體回轉而來，一簡對多繁之字未擇而誤。

## 為何要記

**這類缺陷不觸發任何校驗**：欄位有值、非空、無懸空關聯，字亦是合法漢字。
但它會讓書名與撰人的比對**永遠不合**，於是同一部書被判成「本庫沒有」，接著被重建一遍。
與 `殘名撰人.md` 同族，機理相同：比對用的字串不是真的那個字串。

《隋書經籍志》之 summary 中，「干寶」正作者四見、誤作「幹寶」者十見——
**同一部志書之內即不一致**，故任何「以某源必正」的假設都不可恃。

## 改必逐字有據，不可一律回轉

**人名之是非以本庫 `authors[].name` 所見者為判**：範居姓位者誤（範甯、範梈、範守己），
居名位者不誤（桓範、張弘範、吳範、蕭子範、陳祖範）。此判準可自驗，不待外據。

**逐名列舉是走不通的**——第一輪列了二十六個名，第二輪仍撿出一千一百八十處。
凡此類「一字散在全庫」之缺陷，須找到一個**可判位置的規則**，而非窮舉其詞。
此處之規則是「前一字是不是界」：`《范泰集》`「案范書」`"范德機"`——姓恆在界後；
而洪範、師範、桓範、祖範——範居詞中或名末，其前必是實字。規則可自驗，故可常駐為校驗。

## 改題名須連帶三事

題名一改，`Work/{…}/{id}-{title}.json` 之檔名、`index/*/*.json` 之 `title` 與 `path`、
以及他條之 `related_works[].title` 皆須同步，否則 `chk.py` 之
「索引欄位不符」「related_works[].title 漂移」立見。本輪改名 73 檔（含 fragments 檔）。

`git diff --name-only` 預設會轉義非 ASCII 路徑，據之開檔必落空——須加
`git -c core.quotepath=false`。此坑本輪踩過一次。
