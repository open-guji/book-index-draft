# 補 entity 之全庫普查（2026-08-24）

## 〇、先說一件要緊事：production 現無 entity

- production（`open-guji/book-index`）**無 `Entity/` 目錄**，其 `index/entities/` 十六片俱在而**條數為零**。
- 全庫 15,337 個 entity **盡在 draft**。
- 然 production 已升格之 Work 中，**687 條 authors 帶 entity_id**（如《周禮鄭玄注》繫 `1j9678njjg2rr`），
  所指之 entity 在 production **無一存在**——是為**懸空之繫**。

故「entity 直接在 production 上創建」於現況不可行：若新建於 production，
則新舊分居兩庫，draft 之 chk 亦無從驗其繫（draft 之 entity_id 對 draft 之索引核驗）。
**當仍建於 draft**，entity 之升格自為一事，其管線尚未啟。

## 二、D 類須以「代」覆驗——同名未必同人

D 之 4,055 條，以 entity 之代與本書之代／上限相驗：

| 情形 | 數 | 處置 |
|---|---|---|
| 可逕繫（work 已有代且相合） | 2,719 | 繫 |
| entity 無代 | 455 | 繫，然不因之定代 |
| 可逕繫並可定代 | 301 | 繫並定代 |
| **work 已有代而與 entity 不合** | **474** | **不繫，逐條裁** |
| **entity 代晚於本書上限** | **106** | **不繫，逐條裁** |

**相斥之 580 條，未必是 work 錯。**兩造皆可能誤，須逐條斷：

- 《嵇中散集佚文》work 繫 jin 而 entity 繫 three-kingdoms——**嵇康三國魏人，work 誤**
- 《袁凱集》work 繫 nanbeichao 而 entity 繫 ming——**袁凱明初人，work 誤**
- 《周易陸氏述》work 繫 three-kingdoms 而 entity 繫 qin-han——**陸績吳人，entity 誤**
- 《王瓚集》《劉氏集》work 繫 nanbeichao 而 entity 繫 ming——**同名之陷，二人異**

## 四、擬行之序

**第一步（已行）**：D 之可繫者 3,475 條 + F 之 167 條，共 **3,642 條**補繫，
不新建一人。附帶為 355 部 work 定代。chk 十五項基線俱零。

**第二步**：裁 D 之相斥 580 條。此步不新建，而**兼正兩庫之誤**——
或正 work 之代，或正 entity 之 dynasty。其中 entity 之誤一經校正，
前此三處「同名之陷」清單（凡 68 條）亦可隨之消解。

**第三步**：新建。建議自**甲等 1,002 名**始——其名兩見以上，
故非偶然之殘句；姓氏與名長俱合；且其 work 多已有代，可循以定 dynasty。
既驗其法無誤，再及乙等 7,015。丙丁二等與 I1〜I4 須手裁，不入批次。

**須守之戒**（SKILL〈史料圈套〉已載）：本庫曾有 13 個「作者」實是夾注碎片，
而竟為之建 entity（外黃人、里翟弟子、舊十四篇今、之以為嬰、問董無心、錄一卷劉向……）。
新建之前必驗其名之像人名與否——此即甲乙丙丁分等之所以立。
