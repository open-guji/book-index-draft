# S1：三項 schema 決策（待裁）

**這是提案，不是既成事實。`SCHEMA.md` 未動，等你裁。**
數字皆為 2026-08-21 於 `902a83ec38` 實測活 Work 74,465 條所得。

三項之所以要一起裁：它們共用一個根問題——**一條 Work 記錄到底代表什麼**。
是一部作品？是一個志書著錄？還是一個實物版本？三者混在一起，就會出現
「《老子》有 54 條注本關係卻無實物、《道德經》有 7 個實物卻只是元趙孟頫寫本」
這種各執一端的局面。

## 決策一：偽託之作的朝代怎麼標

### 問題

《關尹子》託名尹喜（先秦），實宋人作。庫中只有一個 `dynasty`（志書原文）
和一個 `period`（本庫之判）。標先秦則選集錯，標宋則丟了「舊題尹喜」這一層。

### 實測

| 事 | 量 |
|---|---:|
| 有偽託信號者（role 標舊題／託名，或案語、提要、解題中明言舊題某某撰／託名／偽撰） | **459** |
| 其中 `authors[].role` 已寫「舊題撰」「託名」者 | 70 |
| 其中 `period` 為空者 | 106 |
| 朝代分布 | ming 82、qing 58、pre-qin 48、song 46、liao-jin-yuan 31、sui-tang 30、jin 28 |

**不是先秦專有**——先秦只佔 48 條，明清合計 140 條。所以這一項越晚做代價越大的判斷成立。

### 三個選項

| | 做法 | 代價 |
|---|---|---|
| 甲 | 加 `authenticity` 枚舉欄 | 一個新欄，需定枚舉與填法 |
| 乙 | 加 `attributed_dynasty` ＋ `attributed_author` | 兩個新欄，且與既有 `authors[]` 重複 |
| 丙 | 不加欄，全用 `authors[].role='舊題撰'` 表達 | 零新欄，但「舊題」不等於「偽」，表達不足 |

### 建議：**甲，但只標異常，不標正常**

**乙不要做。** 舊題撰人的朝代本就寫在那條 author 的 `dynasty` 上——《西京雜記》
`1ev3bcikfdiww` 已是這個形態：`authors[0]` 是「劉歆·漢·舊題撰」，`authors[1]` 才是
「葛洪·東晉·撰」。再立 `attributed_dynasty` 是同一件事記兩遍，必然漂移。

**丙不夠。** 「舊題某某撰」與「偽書」是兩件事：《論語》舊題孔門弟子記，不是偽書；
《古文尚書》才是。只有 role 一個位置，分不出來。

**故取甲，加一個 `authenticity` 欄，枚舉只有兩個值：**

```json
"authenticity": "attributed | forged",
"authenticity_basis": "string（據何而判，逐條可讀）"
```

| 值 | 何時用 |
|---|---|
| `attributed` | 舊題某某撰，實出他手或不可考。書本身不假，只是撰人之題不確 |
| `forged` | 後人偽造而託之於古。《古文尚書》《關尹子》之屬 |
| **省略** | **無疑義。這是絕大多數。** |

**關鍵是不設 `genuine`。** 設了就得給七萬條填，而其中六萬九千條本無疑義。
這與 `loss_status` 同理——庫中 `extant` 只有 1 條，省略即今存。**只標異常，
不標正常**，是本庫既有的體例，不另立新規。

**與 `period` 的關係，一併定死**：

> `period` 一律標**成書時代**（實際撰人之時），不標舊題撰人之時。
> `period_basis` 須寫明「舊題某某（某代），實某代作，據某某」。
> 舊題撰人仍列於 `authors[]`，role 作「舊題撰」，其 `dynasty` 保留志書原文。

如此《關尹子》：`period: song`、`authenticity: forged`、
`authors[0]` = 尹喜·先秦·舊題撰。三層信息各得其所，一層不丟。

**施行**：459 條逐條核（不可機械——「偽」字出現在提要裡未必說的是本書），
分兩批：70 條 role 已標者先做（有現成判準），餘 389 條讀提要原文。

## 決策二：原典與注本的層級

### 問題

一部經有幾百家注。注本該不該獨立成 Work？題名怎麼寫？跟原典什麼關係？

### 實測——**這一項比先秦那份筆記所說的小得多**

庫中**原典錨的機制早已建成並運轉良好**：

| 原典錨 | 繫其下之注本數 | 實物 |
|---|---:|---:|
| 周易 `1evl7l48e27ls` | **1,041** | 14 |
| 偽古文尚書 `1evd3dbcb0nb4` | 386 | 8 |
| 論語 `1ev7w0euvaeww` | 379 | 12 |
| 詩經 `1evl7hsxvr7cw` | 379 | 11 |
| 孝經 `1evl1xugdoikg` | 300 | 8 |
| 左傳 · 漢書 · 禮記 · 周禮 · 儀禮 · 孟子 · 公羊傳…… | 252～93 | — |
| **合計 55 個錨** | | |

關聯詞亦已到位：`contains_text_of` 4,472 ／ `text_carried_by` 4,486，兩側對稱。

**所以缺的不是機制，是把剩下的掛上去：**

| 事 | 量 |
|---|---:|
| `authors[0].role` 為真注疏類者（注 945、傳 36、校 28、述 19、集解 15、集注 12…） | 1,057 |
| 其中題名已含注者名（合規） | 110（已繫原典 100） |
| 其中題名不含注者名 | 947（**已繫原典 306，未繫 641**） |
| 其中題名與某個原典錨**完全同字**（最危險） | **16** |

那 16 條之中還有數條**本身就是錨**——《左傳》`1ev7vo50ar94w` 的 `authors[0]`
是「左丘明·傳」，那不是注本誤題，那就是原典（左丘明傳《春秋》，「傳」是它的體裁）。
**真正需要正名的遠少於 16。**

### 建議：**分兩步，先補關聯，再議正名**

**第一步（可立刻做，零風險）**：把 **641 條未繫原典的注本**補上
`contains_text_of` → 對應原典錨，原典側補 `text_carried_by`。
這是純增量，不動任何既有題名，做完立刻讓「周易有哪些注本」查得全。

**第二步（待第一步做完再議）**：正名。**且只對題名與原典錨完全同字者**，
逐條核——像《周禮注疏》《春秋穀梁傳集解》這種題中已有體裁字樣的**不必改**，
冠上注者名反而累贅。

**寫進 SCHEMA 的規則只有一句**：

> `authors[0].role` 為注／傳／疏／箋／集解之屬者，該 Work 是**注本**，
> 必繫 `contains_text_of` 至其原典 Work；原典側繫 `text_carried_by`。
> 題名**與原典錨完全同字時**須冠注者名以別之，否則從其志書原題。

**不新增欄位。** 這一項用既有的 `role` ＋ 既有的關聯詞就夠了。

## 決策三：一條 Work 到底代表什麼——著錄條／版本條／原典條

### 問題

這是三項裡最大的一項，也是《老子》／《道德經》那個死結的根。

| 記錄之實質 | 例 | 特徵 |
|---|---|---|
| **原典條** | 周易 `1evl7l48e27ls` | 無撰人或舊題撰人，繫千百條注本 |
| **著錄條** | 老子 `1evcmnccovx1c`（隋志著錄，撰人「梁曠」） | 有 `indexed_by`，無實物，其撰人是志書所記 |
| **版本條** | 道德經 `1evkaeh09axhc` | 有 7 個 Book，description 講的是元趙孟頫寫本這一個版本 |

三者混在一條，就會「往任一方向合併都丟結構」。

### 實測——規模比想像大

| 事 | 量 |
|---|---:|
| `ai_note` 明記「本 Work 條目從《某某》目錄錄入」者，即**版本條** | **15,461** |
| ├ 國立故宮博物院善本舊籍 | 8,623 |
| ├ 續修四庫全書 | 3,758 |
| ├ 四庫全書存目叢書 | 2,401 |
| └ 中華再造善本 | 679 |
| 其中**兼有志書著錄**（版本條與著錄條混在一條） | **7,123** |
| 其中 `books` 為空（錄了版本目錄卻沒繫實物） | 5,849 |

**15,461 條佔全庫 21%。** 這不是邊角料。

### 三個選項

| | 做法 | 代價 |
|---|---|---|
| 甲 | 把版本條降級為 Book，Work 只留作品層 | 方向正確，但 15,461 條一次做不完，且做之前得先能分辨哪些是版本條 |
| 乙 | 加 `record_kind` 欄，先把「這條扮演什麼」記下來，再逐步收斂 | 一個新欄，可機械標注 |
| 丙 | 不動，靠 `books[]` 與 `indexed_by[]` 之有無隱式區分 | 零成本，但分不出來——7,123 條兩者都有 |

### 建議：**乙，且乙是甲的前置而非替代**

```json
"record_kind": "work | edition | catalog_entry",
"record_kind_basis": "string"
```

| 值 | 意思 | 現可機械標注者 |
|---|---|---|
| `edition` | 本條描述的是**一個實物版本**，非一部作品 | 15,461 條（ai_note 已明記其所自出） |
| `catalog_entry` | 本條描述的是**某志之一條著錄**，非傳世之書 | 有 `indexed_by` 而無 Book 者 |
| **省略** | 本條是**作品**本身。這是預設 | 其餘 |

**同樣只標異常。** 預設值 `work` 不寫進檔案。

**為什麼乙不是拖延**：甲（降級為 Book）要先知道哪 15,461 條該降，而那正是乙產出的東西。
先標，再逐批降——**降一批，`record_kind: edition` 就少一批**，收斂是可度量的。

**先做哪一批**：5,849 條「錄了版本目錄卻沒繫實物」的——它們既不是作品也沒有實物，
是三類裡最空的，**很可能該直接併入同題之作品條**，而不是另立。

### 這一項若不做，後果是具體的

升格是按 Work 走的。15,461 條版本條若原樣升格到 production，
production 就會出現「同一部《東堂集》有一條作品、七條版本，各自是獨立的書」。
**而升格不可逆**——草稿檔會被削成五個欄的墓碑，到那時再想合就只能改 production。

## 三項合起來：新增的欄一共三個

```json
"authenticity":     "attributed | forged",              // 決策一，省略＝無疑義
"authenticity_basis": "string",
"record_kind":      "edition | catalog_entry",          // 決策三，省略＝作品
"record_kind_basis": "string"
```

決策二不新增欄位。

**貫串三項的一條體例**：**只標異常，不標正常。** 庫中既有先例——
`loss_status` 之 `extant` 全庫只有 1 條，省略即今存。七萬條記錄裡，
無疑義的作品是絕大多數，給它們一律填一個 `genuine` / `work`，
除了製造七萬行 diff 之外沒有任何收益。
