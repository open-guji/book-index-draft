# 一、前幾輪學到的（做之前先讀這一節）

## 1. 錯在「輸入」比錯在「推理」難察覺

玉函山房那一輪誤建三十條，不是推理錯了。當時我看《後漢書（謝承）》，
理由是「同題六家而撰人無一相合，故非一書」——這個推理是對的。
**錯在候選集本身**：候選集出自「題名精確相等」的比對，而庫中同一部書有三四種題法
（《六藝論》／《鄭玄六藝論》／《六藝論鄭玄撰》），於是候選集裡根本沒有那部書。

推理錯了會覺得心虛，輸入錯了反而覺得自己很嚴謹。**凡結論是「庫中沒有」，
先疑候選集，不疑推理。**

## 2. 比對用四法，缺一則誤建

| 法 | 所解之題法 |
|---|---|
| 題名全等 | — |
| 剝撰人之素題 | 《六藝論》／《鄭玄六藝論》／《六藝論鄭玄撰》 |
| 剝官爵之素題（可疊） | 《徐禪集》／《尚書左丞徐禪集》／《給事中徐禪集》 |
| 互為子串 | 《辨腳弱方》／《徐文伯辨腳弱方》 |

四法俱無所得方可新建。有子串相關者一律不建，另出清單待人逐條裁——
子串關係有三解（同書詳略／部分與整體／通名相撞），機器分不了。

## 3. 比對永遠不合的三種靜默缺陷

欄位有值、非空、無懸空關聯，`chk.py` 全綠，但比對用的字串不是真的那個字串：

| | 例 | 察法 |
|---|---|---|
| 殘名撰人 | 「馬彪」實是司馬彪；「逸」實是王逸 | `known-issues/殘名撰人.md` |
| 簡轉繁過度轉換 | 幹寶／硃育／範汪／釧會 | `chk.py` 已立驗，基線 0 |
| 部首區字碼 | ⻢ U+2EE2 ≠ 馬（NFKC 不管此區） | 新建前先驗字碼 |

**動手新建之前，先對 `known-issues/README.md` 的「開工前該對哪一張」。**

## 4. 找得到「可自驗的判準」，才動；找不到，就記下來

- 範→范：逐名列舉走不通（列了 26 個名，第二輪仍撿出 1,180 處）。
  改立**姓位之判**（前一字是不是界），一判全收，而洪範、師範大學、桓範集皆安然。
- 範後接范曄敘述語（範書、範闕、範作）617 處：偽陽約一成半，真偽混處同一批檔
  不能以欄位分——**沒有可自驗的判準之前不動**，數目與偽陽之式記在案。

判準能自驗，才能常駐為校驗；不能自驗的，寫進 known-issues 等下一次。

## 5. 驗算：外部對數 > 內部不變量 > 抽樣

| 法 | 例 | 力度 |
|---|---|---|
| 兩個獨立來源對數 | 汪本標姚氏 419／本庫錄自姚本 420；薛瑩 10/10、謝沈 11/11 | 最強 |
| 文本自身的不變量 | 八家序號各自從一起逐條加一——一舉逼出五種解析缺陷 | 強 |
| 抽樣 | 抽十條看 | 最弱 |

序號連續性那一次尤其值得記：修完只剩謝承兩條同號 389——**那是原書之誤**。
好的驗算能把「我的錯」與「書的錯」分開。

## 6. 解析外部全文：先數體例，再選底本

- **先數**：八家後漢書之佚文行 1,934、校注行 1,843、篇題 490、續行 540。數清了才寫正則。
- **選底本**：kanripo（繁體、標底本、逐半葉標頁、**縮排即結構**）勝殆知閣（簡體、無版本、
  縮排盡失）。同一部經義考，kanripo 得 9,130 條，殆知閣猜得 7,339 條——差一千八百。
  **縮排即結構者，勿以正則猜體例。**
- 規則先嚴，缺者以不變量補；反之（先寬後濾）必生假條，且假條長得像真的。

## 7. 三個「數」不是一個數

| 欄 | 義 |
|---|---|
| `collectors[].count` | 該輯家自己輯得幾條 |
| `collectors[].attested_count` | **別人的輯本說他輯得幾條**（並記其所出） |
| `coverage.fragments_recorded` | 本庫已錄幾條 |

混之則對帳無從做起。同理 `cited_in`（佚文從哪部書引出）與 `collected_by`（誰輯進自己的書）
是兩軸，合為一欄則二者俱失。

## 8. 別人的判斷是「某書如此判」，不是事實

《經義考》逐書判存佚，看似可直接填 `loss_status`。**不可**——四庫御製題論此書自云
「所注闕佚未見者，今四庫所録往往其書尚存」。朱氏之判是十七世紀一人之見聞。
故記為 `indexed_by[].attested_status`。「未見」尤不可轉為 lost：那是著者沒見過。

## 9. 不可對齊者不硬對齊

姚本與汪本同輯後漢諸家，字面相去甚遠，以去標點字串相比 1,922 條僅得 135 對。
取並存，於 `coverage.note` 就地寫明「此數是兩本之和，非佚文實數」。
**硬對齊之害不在漏，在於錯合之後兩條各記的一分事實都沒了。**

## 10. 幾個反覆踩的坑

- `cd A && python3 script.py`：cwd 隨之改，腳本裡的相對路徑全落空。本輪踩了四次。**用絕對路徑。**
- `git diff --name-only` 預設轉義非 ASCII 路徑——須加 `git -c core.quotepath=false`。
- 改題名必連帶三事：檔名、`index` 之 `title`/`path`、他條之 `related_works[].title`。
- `'' in '◇○'` 是 True——空字串判成員永遠真。
- 網路：只通 github.com／gitlab.com。ctext、wikisource、archive、kanripo.org 全不通。
  全文只能自 GitHub 取（daizhige 15,697 種簡體／kanripo 9,355 種繁體）。

# 三、工序設計

依既定次序：**志書 → 考證類書 → 逐條 → 殘缺全佚**。但在此之前須先補一道地基。

## 第〇步（地基）：時代軸與存佚軸

**不做這一步，「整理秦漢的所有古籍」連「哪些是秦漢的」都選不出來。**

### 0a　朝代受控詞彙

現有 106 種寫法，且**歧義是實質的**：

| 詞 | 數 | 歧義 |
|---|---|---|
| 魏 | 272 | 曹魏？北魏？（另有 三國魏 160、北魏 12、後魏 6） |
| 齊 | 59 | 南齊？北齊？（另有 南齊 5、北齊 10、南朝齊 3） |
| 宋 | 4,611 | 趙宋？劉宋？（另有 南朝宋 78、劉宋 7） |
| 周 | 284 | 西周？東周？（另有 北周 13、後周 8） |
| 漢 | 969 | 西漢？東漢？（另有 東漢 486、西漢 5、後漢 3） |
| 雜 | — | `@`、`明0`、`康熙四十八年`、`(清)`、`未詳`…… |

**做法**：立一份 `dynasty` 受控詞彙表（SCHEMA），並**加一個獨立的 `period` 軸**——
`period` 取粗粒度且無歧義（`pre-qin` / `qin-han` / `wei-jin-nanbeichao` / `sui-tang` / …），
由 `dynasty` 推導，推不出者留 null。
**不合併 `dynasty` 之原文**——「魏」是志書原文，改之則失其所本；`period` 是本庫之判，另立一欄。

判準須可自驗：三國魏→`wei-jin`，北魏→`wei-jin`，而單一個「魏」**推不出，留 null**，
另出清單待裁（272 條，可據其書之著錄志書斷——見漢志之於先秦兩漢）。

### 0b　`loss_status` 的覆蓋率

現在 4.5%。「處理殘缺、全佚的書」以此欄為前提。
可靠的來源有三，皆是**證據而非推論**：

1. 志書自身之語：隋志注「亡」、「殘缺」、「今闕」——本輪已用，可推廣到他志。
2. 有輯佚檔且 `collectors` 非空 → 其書必已佚（有人為之輯）。
3. 別人的判（經義考之存佚）——**記為 `attested_status`，不上升為 `loss_status`**。

## 第三步：逐條檢查

上兩步做完，秦漢一區的條目才算齊。逐條之工序（沿用 hanzhi-curation 之批次法）：

1. 以 `period=qin-han` 選出集合，估其規模。
2. 逐條看：題、撰人、卷篇數、著錄之志、存佚。**每條須指得出其據**。
3. 重出之裁（`known-issues/疑似重出.md` 之次序：先看出何志 → 再看繫連數 → 逐組決）。
4. 殘名撰人之補（169 條之甲類可機械回復且可自驗）。

## 第四步：殘缺與全佚

1. **全佚而有輯本者**：立輯佚檔，記 `collectors`。已有之整理本
   （玉函山房、後漢書補逸、七家後漢書）先掃一遍還有哪些秦漢之書可繫。
2. **全佚而無輯本者**：`loss_status: lost`，`fragments` 檔可不立——但須記其「無輯本」是
   查過的還是沒查（**「查不到」有三種**：體例不收、遍檢不見、根本沒查）。
3. **殘缺者**：`partially_extant`，並記殘之所在（卷數之異、篇數之闕）。

# 四、次序之由與先做什麼

第〇步是地基，但可以**只做秦漢那一段**——不必一次立全部朝代的 `period`，
先把 秦／漢／新／三國 這一段的判準立起來，覆蓋約 1,800 條（漢 969＋東漢 486＋
西漢 5＋後漢 3＋秦 17＋三國魏 160＋三國吳 44＋三國蜀 24＋蜀 36＋魏 272 之可斷者）。
如此第一步之驗算才有集合可算。

**建議先做**：0a（秦漢段之 period）＋ 第一步之 1、2（漢志補略、以總計驗算）。
這兩件不需要新文本，庫裡的料就夠，且做完立刻能回答「秦漢一共有多少書、漢志收全了沒有」。

第二步要你上傳文本。可以並行——你傳的時候我做第一步。
